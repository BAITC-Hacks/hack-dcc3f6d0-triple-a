# AI Sana Challenge Hub

MVP площадки на Python 3.11, Streamlit и SQLite. Бизнес описывает задачу, получает минимум три уточняющих вопроса, проверяет предложенные поля карточки, подтверждает сведения и публикует задачу. Команды выбирают её и отправляют идею, план и ссылку; бизнес вручную принимает одну, несколько либо ни одной команды.

## Запуск в Windows PowerShell

Из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Нужен установленный Python 3.11, доступный командой `python`. Активация окружения и изменение политики PowerShell не нужны. Если `.venv` и зависимости уже установлены, выполните только последнюю команду. Откройте `http://localhost:8501` (или адрес, указанный Streamlit).

При первом запуске создаётся `sana_hub.sqlite3` с 5 синтетическими исходными задачами и связанными карточками, 5 командами и 5 предложениями. Повторный запуск не дублирует записи. Существующая база сохраняется: новые столбцы добавляются при запуске, старые карточки и решения не перезаписываются демонстрационными данными. Новые демонстрационные примеры появляются только в новой базе.

Без ключа работают локальные уточняющие вопросы. Для OpenAI API задайте переменную окружения в том же окне PowerShell перед запуском:

```powershell
$env:OPENAI_API_KEY = "ваш_ключ"
.\.venv\Scripts\python.exe -m streamlit run app.py
```

При необходимости задайте `$env:OPENAI_MODEL = "gpt-4o-mini"`. `.env.example` служит образцом: приложение не читает `.env` и берёт ключ только из переменной окружения. Ключ не вводится в интерфейсе. OpenAI используется для вопросов и предложений полей через [официальный Python SDK и Responses API](https://developers.openai.com/api/docs/quickstart).

Без ключа, при ошибке API или неправильном формате ответа работает локальный резерв. Фактический режим показан у вопросов и предложений. Предложенные значения берутся дословно из черновика или ответов; источник виден рядом. Локальный режим понимает строки вида `Название: ...`, `Контекст: ...`, `Пользователи: ...` и ответы на вопросы. Свободный черновик может переноситься целиком в контекст; неизвестные поля остаются пустыми. AI не подтверждает поля и не выбирает команды.

## Демонстрация

1. Выберите роль «Бизнес» в боковой панели, откройте «Работа бизнеса». Введите описание задачи и получите уточняющие вопросы.
2. Заполните ответы и нажмите «Сохранить ответы и предложить поля карточки». Просмотрите предложения и источники. Нажмите «Применить предложения к пустым полям»: введённые вручную значения сохранятся, новые значения будут неподтверждёнными.
3. При необходимости отредактируйте карточку и сохраните текст. Затем отдельно отметьте проверенные поля и нажмите «Подтвердить выбранные поля». Изменение ранее подтверждённого текста сбрасывает его подтверждение при сохранении.
4. Посмотрите уровень и разбивку по семи критериям; вручную опубликуйте карточку. Нужен осмысленный заголовок, порога баллов нет. Неопубликованные карточки видны в каталоге, но отклики принимаются только после публикации — даже при 0 баллов.
5. Выберите роль «Команда» и профиль команды. В «Работа команды» выберите задачу, введите идею, план и HTTP(S)-ссылку. Там же можно добавить новую команду.
6. Вернитесь в роль «Бизнес», выберите задачу и сохраните решение по каждому предложению. Можно принять несколько команд, отклонить все или оставить предложения на рассмотрении.

Пример черновика для показа:

```text
Название: Помощник агронома
Контекст: Агрономы составляют планы обхода вручную.
Потребность: Нужен помощник для планирования работ по культуре, погоде и симптомам.
Пользователи: Агрономы
Ожидаемый результат: План работ на неделю.
```

Это пример задачи на площадке: сам агрономический помощник не является частью Hub. Неизвестные данные, контакты и ограничения уточняет бизнес.

Баллы рассчитываются кодом только за содержательно заполненные и вручную подтверждённые группы: контекст и потребность — 20; данные — 20; результат — 15; критерии успеха — 15; ограничения — 10; пользователи — 10; контакт и формат взаимодействия — 10. Для парных групп нужны оба поля, иначе весь критерий даёт 0. Название баллов не даёт. Пустые строки, пунктуация и явные заглушки вроде `не знаю`, `нет данных`, `TBD` не засчитываются. Проверка заглушек не доказывает истинность сведений: их проверяет человек.

Уровни: 0–39 — черновик; 40–69 — рабочая постановка; 70–89 — готова; 90–100 — приоритетная. Уровень готовности и состояние публикации независимы.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверки используют отдельные временные базы и имитации API, не меняют рабочую SQLite и не обращаются к реальному OpenAI. Основной сценарий проверяется через Streamlit AppTest, включая ручное подтверждение, публикацию, отклик и выбор команды.

Код: `app.py` — интерфейс; `storage.py` — SQLite и правила сохранения; `questions.py` — вопросы и предложения полей; `rating.py` — рейтинг. Демонстрационные записи пока находятся в `storage.py`.

## Границы MVP

Переключатель ролей и профилей предназначен для доверенной демонстрации; полноценной авторизации нет. Старые задачи при миграции привязываются к демопрофилю бизнеса. Выбор команды полностью ручной.

Этап «Прототип показан» и начисление команде +10 пока не реализованы. Работа с реальным OpenAI зависит от ключа, доступа к модели и сети; живой запрос в текущей проверке не выполнялся. Поиск заглушек и извлечение цитат не заменяют проверку человеком.
